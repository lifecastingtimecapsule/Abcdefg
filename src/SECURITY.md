# セキュリティガイド

このドキュメントは、アマレット管理システムのセキュリティに関する重要な情報をまとめています。

## 実施済みのセキュリティ対策

### 1. ✅ トークンログの削除
**リスク:** アクセストークンがコンソールに出力されることで、情報漏えいのリスクがありました。

**対策:**
- すべての `console.log` からトークン情報（トークン本体、長さ、プレビュー）を削除
- 対象ファイル: `/utils/api.ts`, `/App.tsx`, `/components/LoginPage.tsx`

### 2. ✅ 型安全性の向上
**リスク:** `any` 型の多用により、型安全性が低く、保守性・品質保証が困難でした。

**対策:**
- `/types/index.ts` に共通型定義を作成
- 主要なコンポーネントとAPI呼び出しに型を適用
- `User`, `Customer`, `Reservation`, `WorkOrder` など業務データに明確な型を定義

### 3. ✅ 401エラーハンドリングの改善
**リスク:** 401エラー時に即座にリロードするため、ユーザーの入力データが失われる可能性がありました。

**対策:**
- コールバック機構を実装（`setUnauthorizedCallback`）
- 将来的に再ログインモーダルなどの実装が可能な構造に変更

## 既知のセキュリティ制約（環境上の制限）

### ⚠️ localStorage によるトークン管理
**リスク:** XSSやブラウザ拡張機能による不正アクセスのリスク

**現状:**
- Figma Make 環境の制約により、HttpOnly Cookie の完全実装は困難
- Supabase SDK も内部的に localStorage を使用

**緩和策:**
- 適切なCSP（Content Security Policy）の設定を推奨
- トークンの有効期限を短く設定
- 定期的なトークンのローテーション

### ⚠️ 環境変数の扱い
**現状:**
- `/utils/supabase/info.tsx` は自動生成ファイル（変更不可）
- プロジェクトIDと anon key がコード内にハードコード

**注意事項:**
- `publicAnonKey` は公開前提の設計（Supabase の仕様）
- **絶対に `SUPABASE_SERVICE_ROLE_KEY` をフロントエンドに含めないこと**
- 環境の切り替えはビルド時に自動生成ファイルが更新される仕組み

## セキュリティベストプラクティス

### 開発時
1. **機密情報のログ出力禁止**
   - トークン、パスワード、個人情報をログに出力しない
   - デバッグ時も必ずマスクする

2. **型安全性の維持**
   - 新しいAPI呼び出しには必ず型定義を追加
   - `any` 型の使用を避ける

3. **エラーハンドリング**
   - すべてのAPI呼び出しに適切なエラーハンドリングを実装
   - ユーザーに詳細なエラー情報を見せない（内部エラーはログのみ）

### 運用時
1. **アクセス制御**
   - 管理者権限（admin）と一般スタッフ（staff）を適切に分離
   - 定期的な権限の見直し

2. **監査ログ**
   - 重要な操作（顧客情報の変更、制作物のステータス変更など）はサーバー側でログを記録

3. **定期的なセキュリティレビュー**
   - 依存パッケージの脆弱性チェック
   - トークンの有効期限管理
